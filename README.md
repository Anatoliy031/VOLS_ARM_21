# Рабочее место ППО ВОЛС

Комплект для предпроектного обследования опор ВЛ под размещение сетей электросвязи
и формирования отчёта владельца инфраструктуры по пункту 13 Правил недискриминационного
доступа (ПП РФ от 22.11.2022 № 2106).

Всё работает целиком в браузере. Данные никуда не передаются.

## Главный формат данных

**`ID_shablon.xlsx`** — единственный источник исходных данных. Отчёт всегда собирается
из этой книги, кем бы она ни была заполнена.

Заполнить её можно двумя способами, результат одинаковый:

* **вручную в Excel** — как раньше, по инструкции;
* **через форму «Осмотр»** — она заполняет ячейки ручного ввода за вас.

Форма правит книгу точечно: заливка ячеек, выпадающие списки, именованные диапазоны
и все ~3000 формул шаблона остаются на месте. Материал и тип опоры, состояние по
ГОСТ 31937-2024, лист «Мероприятия» и Блок 1 листа «Нагрузки» по-прежнему считает сам Excel.
Если опор больше, чем строк в шаблоне, строки дописываются вместе с формулами и списками.

Книгу, заполненную вручную, форма читает обратно — кнопка «Загрузить шаблон Excel».

## Сквозной путь: обход в поле → отчёт

1. **Выезды** — сгруппировать объекты по маршрутам, прикинуть поездки и километраж.
2. **Обход** — пройти линию, ставя метки с фотографиями в любом приложении, которое
   сохраняет KMZ (Locus, OsmAnd, Google Earth). Подпись метки — по схеме ниже.
3. **Импорт KMZ** (`potok.html`) — пять шагов: файл → проверка распознанного →
   реквизиты отчёта → перенос → готово.
4. **Измерения** — полевые калькуляторы; каждый результат кнопкой уходит в осмотр.
5. **Отчёт** — «Взять данные из осмотра», затем «Фотографии из осмотра → приложение В».
   Выгрузка: PDF, PDF с водяным знаком, Word.

Шаги 2 и 3 можно заменить ручным вводом в разделе «Осмотр» или заполнением
`ID_shablon.xlsx` в Excel — результат один и тот же файл.

## Подпись метки в поле

    номер : марка : линия : примечание

| Пример | Что понимает импорт |
|---|---|
| `104:П10-1:ВЛ 10 - Сщ-7` | опора 104, марка П10-1, линия ВЛ 10 Сщ-7 |
| `103: УА10-1` | линия наследуется от предыдущей метки |
| `2-5:П3:ВЛ 0,4 №1 ТП Сщ-7 - 4:Отклонение от оси` | примечание даёт категорию дефекта Б |
| `15П10-1:ВЛ 10 - Сщ-4` | пропущенное двоеточие между номером и маркой |
| `Б/С` | первая часть не номер — в опоры не попадает, показывается отдельно |

Что делается автоматически:

* **Линия** указывается только там, где меняется; остальные опоры её наследуют.
* **Класс напряжения** берётся из названия линии (`ВЛ 10` → 10 кВ, `ВЛ 0,4` → 0,4 кВ),
  при отсутствии — из числовой части марки.
* **Полевые сокращения марок** (П3, УА10-1, П10/0,38, АО3, К3) приводятся к маркам
  справочника по типу опоры и классу. Соответствие показывается на шаге 2 — по одной
  строке на уникальное сокращение, а не на каждую опору. Исходное обозначение
  сохраняется в примечании к опоре: «по данным осмотра — П3».
* **Совмещённые опоры** ВЛ 10/0,4 кВ отмечаются в примечании.
* **Пролёты** считаются по координатам соседних опор внутри линии, в порядке обхода.
* **Категория дефекта** распознаётся по ключевым словам примечания: разрушение, оголение
  арматуры → A; отклонение, наклон, трещины → Б; сколы, загрязнение → В.
* **Даты работ** берутся из отметок времени меток.
* **Фотографии** извлекаются из архива, сжимаются до 1600 px и привязываются к опорам.
  Снимки опор с дефектами попадают в приложение В отчёта автоматически, с подписью вида
  «опора № 102, ВЛ 10 - Сщ-7 — дефект категории Б, ограниченно работоспособное состояние».
  Остальные добавляются кнопкой «Все фото из осмотра».

На шаге 2 можно снять лишние линии, поправить любое соответствие марок и увидеть метки,
не ставшие опорами. Ничего не переносится, пока вы не нажмёте «Перенести».

## Автоматический вывод по измерениям

В форме вводится только замеренное число. Норматив подставляется по классу напряжения,
характеру местности, удельному сопротивлению грунта или типовому проекту, вывод
«соответствует / не соответствует» считается сам. Охвачены все 13 видов измерений
справочника: отклонение стойки от вертикали, прочность бетона, габариты провода и ОК
до земли, расстояния ОКСН до провода и элементов опоры, глубина заложения, диаметр стойки,
раскрытие трещин, защитный слой, сопротивление заземления, расстояния между точками крепления.

Несоответствия автоматически попадают на лист «Мероприятия».

Опоры выбираются группой: галочками, целой линией, диапазоном номеров или по наличию
дефекта. Одно замеренное значение записывается отдельной строкой на каждую выбранную
опору — это обычный случай, когда результат одинаков для всей линии или для группы
однотипных опор. Работает и в полевых калькуляторах, и в форме осмотра.

## Измерительные инструменты

| Инструмент | Что делает |
|---|---|
| Отклонение стойки от вертикали | Датчик наклона устройства или пересчёт из замера рулеткой в вид 1/N |
| Высота опоры и точки подвеса | По углу визирования и расстоянию; подставляется в кренометр |
| Габарит до земли | Прямой замер или расчёт через стрелу провеса `f ≈ qL²/8H` |
| Прочность бетона | Серия отсчётов, отбраковка отклонений свыше 10 % по ГОСТ 22690-2015, коэффициент вариации |
| Ширина раскрытия трещин | Экранный эталон с калибровкой по банковской карте (85,6 мм) |
| Сопротивление заземления | Норматив по удельному сопротивлению грунта (ПУЭ-7 гл. 2.5) |
| Пролёты по координатам | Расстояние между точками; заполнение пролётов всей линии разом |
| Компоновка ОКСН | Пять нормируемых расстояний за один заход, запись пачкой |
| Запас несущей способности | Прикидка изгибающего момента до и после подвески ОК |
| Ёмкость опоры | Сколько кабелей ещё поместится с шагом 0,30 м |

Датчики устройства дают ориентировочную точность. Для отчёта используется поверенный
прибор; калькуляторы служат для проверки и пересчёта.

## Границы отчёта

Раздел 1.5 отчёта разграничивает предмет работ.

**В отчёт входят:** визуальный осмотр опор с категорией состояния по ГОСТ 31937-2024;
инструментальные измерения; учёт ранее размещённых элементов сетей связи; сводная оценка
технологической возможности.

**В проектную документацию пользователя** (в отчёте — рекомендательно): поверочные расчёты
нагрузок по ПУЭ-7 и СП 20.13330.2016; выбор марок кабеля, узлов крепления и арматуры;
точки и высоты подвеса, стрелы провеса, тяжения; технические решения по устранению
дефектов; мероприятия по пп. 3–5 ТТ № 282р. Основание — пункты 5.1 и 6 ТТ № 282р.

## Как данные проходят через шаблон

Формулы Excel вычисляет сам Excel — только при открытии файла. Разбор книги в браузере
видит в таких ячейках пустоту. Поэтому производные столбцы восстанавливаются дважды,
независимо друг от друга:

* при выгрузке в отчёт форма подставляет их из справочников сама;
* генератор отчёта дополнительно достраивает недостающее (`backfill`) — материал и тип опоры,
  дефект, состояние по ГОСТ, технологическую возможность, мероприятие, характеристики кабелей,
  Блок 1 листа «Нагрузки» и лист «Мероприятия».

Благодаря этому отчёт получается одинаковым независимо от того, откуда пришли данные:
из формы осмотра, из скачанного шаблона, загруженного обратно, или из книги, в которой
формулы кто-то стёр вручную.

Сквозная сверка «модель → шаблон → обратно» проверяет поля по всем листам и справочникам;
расхождений быть не должно.

Справочник опор в книге Excel и в веб-форме — один и тот же: при сборке шаблона он
выгружается из `ppo-core.js`, поэтому разойтись они не могут.

## Внутренний аудит

При формировании отчёта выполняются 43 автоматические проверки в шести группах
(комплектность, непротиворечивость, метрология, сроки, несущая способность,
разделение ответственности). Результат — на панели и в «Листе внутреннего контроля
качества». При несоответствиях отчёт помечается как не подлежащий выпуску.

Блокирующие проверки, введённые по результатам разбора выпущенных отчётов:

| Группа | Что ловится |
|---|---|
| Непротиворечивость | сумма по технологической возможности ≠ числу опор; аварийные опоры сложены с ограниченно работоспособными; счётчик категорий ≠ ведомости; число мероприятий ≠ строкам приложения Е |
| Непротиворечивость | дефект «отклонение» при выводе «соответствует» в протоколе по той же опоре |
| Непротиворечивость | высота подвеса меньше нормируемого габарита ОК до земли |
| Метрология | одна опора × один вид измерения записаны дважды с разными значениями |
| Метрология | одно значение растиражировано на пять и более опор |
| Метрология | строки протокола без привязки к опоре |
| Метрология | заявленный метод (НК прочности бетона) не подтверждён ни одним протоколом |
| Метрология | категория состояния присвоена по коррозии арматуры без инструментального контроля |
| Несущая способность | в расчёте нет собственных проводов ВЛ; тип ранее размещённых кабелей «не определён» |
| Разделение ответственности | мероприятие группы Е.2 возложено на пользователя инфраструктуры |
| Разделение ответственности | выявлены аварийные опоры без отметки о передаче в эксплуатацию |
| Комплектность | менее двух исполнителей, нет наряда-допуска или схемы работ; не указан источник климатических данных; не заполнены «исходные данные» и «работы, не выполнявшиеся»; не описаны линии |
| Сроки | регистрация раньше запроса, договор раньше регистрации, работы раньше оплаты |

## Приложение Ж — методика

Три положения, отличающие текущую версию:

* **Допустимый момент задан по стойке**, а не по назначению опоры: одна стойка не может
  иметь разные допустимые моменты. Подкосы, вторая стойка и оттяжки в запас не учитываются.
* **Расчётный пролёт — наибольший** в пределах марки, а не средний. Для опор в ограниченно
  работоспособном состоянии дополнительно считается вариант с коэффициентом 0,8 к M_доп.
* **Количественный запас выдаётся только для промежуточных опор.** По анкерным, угловым,
  концевым и ответвительным оценка не приводится: они работают совместно с подкосами и
  оттяжками, которых упрощённая схема не описывает. Поверочный расчёт переносится в
  приложение Е.1.

Нагрузки учитываются раздельно по классам напряжения: провода 10 кВ не нагружают опоры 0,4 кВ.

## Разделение ответственности: Е.1 и Е.2

Приложение Е разделено на две части, распределение выполняется автоматически.

| | Е.1 | Е.2 |
|---|---|---|
| Что включено | проектные решения, поверочные расчёты | дефекты конструкций, несоответствия состояния |
| Когда возникло | в связи с размещением | до заявления, размещением не вызвано |
| Исполнитель | пользователь инфраструктуры | владелец инфраструктуры |
| Основание | пп. 5.1, 6 ТТ № 282р | ст. 210 ГК РФ, ПТЭ |

Возложение мероприятий группы Е.2 на заявителя как условия доступа образует признаки
навязывания невыгодных условий договора (ч. 1 ст. 10 ФЗ № 135-ФЗ) и блокируется аудитом.

Форма осмотра дополнительно проверяет комплектность до выгрузки: незаполненные
обязательные поля, опоры без марки и пролёта, измерения без описанного прибора,
истёкшую поверку.

## Сохранность данных

Текстовые данные лежат в памяти браузера устройства, фотографии — в его локальной базе.

резервную копию: «Начало» → «Сохранить резервную копию» (`.json`) либо сохраняйте
заполненный `ID_shablon.xlsx`.

## Публикация на GitVerse Pages

Программистом быть не нужно: всё делается мышкой в браузере.

**1. Создайте репозиторий.** В шапке GitVerse нажмите `+` → «Новый репозиторий».
Задайте название (например `ppo-vols`), видимость — **публичный**
(для приватного Pages не работает). Отметьте «Добавить файл README».

**2. Загрузите файлы.** Откройте репозиторий, нажмите «Добавить файл» → «Загрузить файлы».
Распакуйте архив комплекта на компьютере и перетащите **всё содержимое сразу** — все 18 файлов,
не раскладывая по папкам. Внизу страницы нажмите кнопку подтверждения (коммита).
На вопрос о замене `README.md` отвечайте согласием.

**3. Включите Pages.** В репозитории: «Настройки» → «Страницы».
Включите GitVerse Pages, источник — **Ветка**, ветка — `main` (или `master`),
папка — корень `/`. Сохраните. Сборка запустится сама.

**4. Проверьте.** Через пару минут сайт откроется по адресу:

    https://<ваш-логин>.gitverse.site/<название-репозитория>

Ссылка появится на главной странице репозитория. Если название репозитория совпадает
с вашим логином, адрес будет коротким: `https://<ваш-логин>.gitverse.site`

**5. Раздайте коллегам** ссылку на `portal.html` — там встроенная инструкция:

    https://<ваш-логин>.gitverse.site/<репозиторий>/portal.html

### Условия, которые проверяет GitVerse

* репозиторий публичный;
* в репозитории включён CI/CD;
* логин владельца без точек, название репозитория не начинается с точки.

### Как обновить сайт потом

Загрузите изменённые файлы поверх старых тем же способом — сборка перезапустится сама,
сайт обновится через минуту-другую. Ничего пересоздавать не нужно.

### Если сайт открылся, но не работает заполнение шаблона

Страница пишет «Шаблон не найден рядом со страницей» — значит `ID_shablon.xlsx`
не загрузился в репозиторий или лежит в подпапке. Проверьте, что он в корне.

Открывать файлы двойным щелчком с диска (адрес начинается с `file://`) нельзя:
браузер запретит подгрузку шаблона. Работает только по ссылке на сайт.

## Изменения текущей версии

**Резервная копия сохраняет фотографии.** Снимки хранятся не в общем хранилище, а
в отдельной базе браузера (IndexedDB), и прежняя копия их не захватывала. Теперь
кнопка «Резервная копия (.json)» упаковывает изображения внутрь файла, а рядом
появилась кнопка «Восстановить из копии». Файл из-за этого весит существенно
больше — это ожидаемо. Копии, сделанные прежней версией, читаются по-прежнему,
но фотографий в них нет.

**Метки, не ставшие опорами, больше не теряются.** Список, который раньше жил
только на экране мастера импорта, сохраняется вместе с объектом и показывается
на вкладке «Осмотр» → «Опоры»: подпись, координаты, число снимков. Метку можно
превратить в опору (координаты и исходная подпись переносятся в карточку) либо
убрать из списка.

**Вкладка «Дефекты»** — между «Измерения» и «Приборы». По каждому дефекту
задаются описание из осмотра, исполнитель мероприятия (владелец инфраструктуры /
пользователь / определяется проектной документацией), срок выполнения и
ориентировочная стоимость. Эти сведения идут в лист «Мероприятия» книги и в
приложения В и Е отчёта. Карточка дефектной опоры на вкладке «Опоры»
подсвечивается красным целиком.

**Приложение В отчёта.** В шаблоне графы «Дефект» и «Примечание» — формулы
VLOOKUP, а правка книги намеренно сбрасывает их кэш, чтобы Excel пересчитал
значения; браузер формулы не вычисляет, поэтому графы приходили пустыми. Теперь
примечание собирается как «наблюдение осмотрщика + типовое последствие по
категории», в генераторе отчёта стоит подстраховка по справочнику дефектов, а
подписи под фотографиями содержат текст дефекта, а не только его категорию.

**Срок предоставления информации.** Из служебных отметок убрана фраза про
30 рабочих дней. Расчётная предельная дата берётся из нового поля паспорта
«Дата исполнения обязательств по договору (счёту)» (вкладка «Объект», группа
«Запрос»). Проверка внутреннего аудита переформулирована соответственно.

**Пункт 6.1** — второй абзац сокращён до «Распределение обязанностей по
выполнению мероприятий определяется договором.»

**Приложение Ж.2** — устранено задвоение в графе «Сведения»: «Нормативная
толщина стенки гололёда» и «Нормативное ветровое давление».

**Форма обязательства о конфиденциальности** — новая страница
`obyazatelstvo.html` (пункт 15 Правил): предмет обязательства, восемь
обязательств пользователя инфраструктуры, изъятия, срок действия и
ответственность, подписи и отметка владельца о регистрации. Заполняется
реквизитами осмотра одной кнопкой, поля правятся прямо на листе, печатается
в ПДФ. Ссылки — в шапке рабочего места, на портале и в панели генератора отчёта.

**Разбор KMZ.** Замечание берётся и из описания метки, если в подписи его не
было: часть полевых программ пишет наблюдение именно туда, и прежде оно
терялось молча.
